# 主页面与面板插件规范

> 目标契约，待评审。适用于自建面板及第三方插件 UI；不表示现有页面、lint 或视觉基线已经达标。产品边界见 [蓝图](./product.md)，现状见 [三页体检](./ui-audit.md)。与旧版 [设计规范](./dev/design-system.md) 冲突的字号、间距、动效、断点以本目标为准，旧代码暂不随文档修改。

## 11 条硬规则

1. **公共组件优先且限七类**：按钮、卡片、列表行、标签、抽屉、页头、输入框。复用现有 `Button`、`Card`、`ListRow`、`Sheet`、`PageHeader` 等；输入与标签尚需统一可复用接口，不能声称七类组件都已齐备。缺少的组件先入公共库再开放面板使用，不允许面板自行定义按钮、圆角或交互语义。原生语义元素保留在公共组件内部。
2. **颜色全部走令牌**：背景、表面、边框、主色、危险、成功、警告、文字八类语义，文字再分主要/次要/弱化三级（不是总共只有八个变量）。自动跟随 light/dark。业务面板禁止硬编码 hex、rgb、hsl、oklch 等色值；颜色生成器、设计令牌源和测试基线作为集中审查的例外，不能为了 lint 把颜色搬进普通变量规避。
3. **字号和间距有白名单**：字号仅 12/14/16/20/24/32，使用公共排版令牌并绑定固定行高，不允许每个面板重新选择行高。间距仅 4/8/12/16/24/32。零间距、边框粗细、图标几何、44px 命中区域及系统安全区不是内容间距；例外须明确归类，不放开任意尺寸。
4. **三态必须齐全**：空态解释内容来源与下一步；加载态保留骨架/进度并有可访问状态；错误态回答“为什么、怎么办”，提供可执行恢复入口。首次加载失败不能冒充空列表，白屏不合格。
5. **布局不能写死**：宽度跟随插槽，声明最小可用宽度；列表走公共虚拟滚动；高度弹性。公共容器的最大阅读宽度、断点、图标与触摸目标允许集中声明，禁止业务面板固定宽高撑坏布局。不能把 `min-width: 0` 当成最小可用宽度声明。
6. **动效克制**：只做进入、退出、状态切换，120–200ms 缓出；系统或用户开启减少动态后取消非必要运动。禁止滚动视差、发光、粒子及装饰性循环动画；必要的加载状态不得仅靠动画传达。
7. **背景分层**：每个可见面板最多两层表面色、一个强调色，不靠满屏边框或阴影制造层次。危险/成功/警告用于状态，不变成第二个品牌强调色。
8. **中英文案、一个图标库**：所有产品文字走 i18n，中文与英文同交付；用户内容不强行翻译。统一使用现有 Phosphor 图标映射，不用 emoji 代替功能图标，图标有可访问名称或明确装饰标记。
9. **可访问性**：焦点可见、键盘能走完，抽屉和浮层关闭后恢复焦点；正文和控件文字对比度至少 4.5:1。禁用和错误不能只用颜色区分；读屏能理解空/加载/出错状态。
10. **截图是合并门槛**：UI 改动必须附手机和桌面截图，并扩展到下节八个视口的固定矩阵。基线按平台分别存放 `web/`、`desktop/`、`android/`，不得跨平台比较。每个适用平台覆盖 light/dark、关键三态、无横向溢出与减少动态。没有所需截图/差异审核不能合并；基线更新不能自动接受回归。
11. **自动拦截**：CI 必须检查硬编码颜色、越界字号、非法间距、业务面板写死宽度，并运行截图比较；规则应有正反例测试与例外清单。不能仅靠人工或普通 Biome 推荐规则声称已实现这些检查。当前仓库尚无上述完整门禁，文档提交不会自动增加它们。

## 自适应与截图验收（与第 10 条不可拆开）

布局变形而不是整体缩放。CSS 像素宽度区间采用无重叠边界：

| 形态 | 宽度           | 插槽行为                                                                |
| ---- | -------------- | ----------------------------------------------------------------------- |
| 手机 | <600           | 单栏；列表/聊天两页互切，右栏进入抽屉；顶栏一个标题、一个主按钮。       |
| 平板 | 600 ≤ w <1024  | 左列表 + 主区两栏；右栏进入抽屉。                                       |
| 桌面 | 1024 ≤ w ≤1440 | 左列表 + 主区 + 右栏三栏，面板宽度不足时按声明折叠。                    |
| 宽屏 | >1440          | 仍为三栏；主区阅读内容约 800px 最大宽度，不把所有表格也强行压到 800px。 |

配套五条：

1. 每个面板声明最小可用宽度，由插槽决定显示、折叠或移出，保留可达入口，不硬挤。
2. 点击/触摸命中区域至少 44×44 CSS px，不能只测图标大小。
3. hover 才出现的操作必须有触摸和键盘替代，不得依赖鼠标存在。
4. 手机安全区保留；软键盘弹出/收起时输入框跟随，列表可滚动、焦点不被遮挡。桌面浏览器改视口不能代替 Android 软键盘实测。
5. 字号不随屏幕缩放；保持系统可访问缩放，不用禁缩放或整体 transform 假装适配。

此前口述“四个断点各一张、共八张”数量不一致。这里明确落实为**每类形态两档、合计八个视口**：手机 360×800 / 390×844，平板 600×960 / 768×1024，桌面 1024×800 / 1280×800，宽屏 1536×960 / 1920×1080。该矩阵是文档提议的可重复默认值，需在评审时确认；不代表现有脚本已覆盖。另测 599/600、1023/1024、1440/1441 边界，检查布局跳变和溢出。

截图固定语言、字体、DPR、主题、数据和动画时钟，屏蔽动态时间但不隐藏失败。Web 可用 Playwright；Electron 固定其 Chromium 版本；Android 在模拟器或真机固定系统 WebView 与字体。手机上适用的面板测手机档；桌面专属入口不得伪造 Android 基线，可在矩阵中注明不适用并解释。差异报告需保存 actual/expected/diff，人工确认美观、层级及触摸行为，不能只看像素阈值。

## 插槽注册边界

注册目标为顶栏、左列表、主区、右栏、浮层之一。注册项需有稳定 ID、最小可用宽度、标题/i18n 键、加载/错误/空态、释放订阅的方法和焦点策略。插件卸载必须移除面板及监听。注册格式见下节；现有 JSX 条件分支已改为注册数据，但面板自身的加载/错误/空态仍由面板负责，注册表不替它渲染。

## 面板注册格式（已实现）

实现位于 `client/src/components/slots.ts` 与 `Slot.tsx`。一个面板就是一条数据，加功能只加一条注册项：

| 字段        | 必填 | 含义                                                                                       |
| ----------- | ---- | ------------------------------------------------------------------------------------------ |
| `id`        | 是   | 稳定 ID，点分小写（`main.chat`、`left.sidebar`）。重复注册直接抛错，不静默覆盖。           |
| `slot`      | 是   | `topbar` / `left` / `main` / `right` / `overlay`。第六个插槽要先改本文档，再改代码。       |
| `titleKey`  | 是   | 标题的 i18n 键，用于无障碍名称与折叠入口的条目。                                           |
| `minWidth`  | 是   | 面板可用最小 CSS 宽度，4 的倍数；`0` 表示永远渲染（主区与浮层），不参与折叠。              |
| `order`     | 否   | 显示顺序，同时是窄槽位的保留顺序：越靠前越晚被折叠。同序按 `id` 排，结果不依赖注册顺序。   |
| `key`       | 否   | 重挂载键；状态属于某个对象（一个会话、一台设备）时用它，避免切换对象后串状态。             |
| `component` | 是   | 零参数组件。面板从上下文取自己需要的状态，不由外壳传参，这样面板身份在路由变化时保持稳定。 |

外壳的判定规则，面板不重复实现：

- 宽度够就显示；不够就折叠进该槽位的「更多面板」入口，入口用 `Sheet` 打开并渲染被折叠的面板，保证可达，不硬挤、不缩字号。
- 未测量到宽度时（服务端渲染、单元测试）一律显示。量不到就把页面藏起来，等于白屏。
- 主区与浮层用 `measure={false}`：它们的宽度由内容决定，折叠会取消整页。
- 内置面板是外壳里的一份数据；运行时注册走同一个 `register()`，返回的 disposer 必须调用，卸载时移除面板与监听。

第三方页面不得覆盖主布局、注入全局重置样式或自行接管导航。不适配时降级到标准卡片容器；若需要隔离执行，另走权限/沙箱边界，样式容器不提供代码安全保证。DSH 原生设置保留其官方组件和写入语义，由宿主提供导航和容器，不强行重写成另一套表单。
