# 记忆

在桌面、手机或网页 App 主菜单中打开 **记忆**。你可以添加、编辑、删除单条事实，或打开主题编辑 Markdown。被拒绝的改动会显示服务器的原因。所有 App 共用服务器记忆，不在各端另存一套。

助手可以调用 `remember`（文本及可选主题）、`forget`（条目文本或 id）、`recall`（列出全部、用 `query` 搜索，或用 `topic` 读取整个主题）。在相同位置重复保存相同文本，只会安静地提示已保存过。本版本不做自动整理。

每个会话首次渲染提示词时冻结记忆块。之后保存的新记忆不会改变该会话的系统提示词，以便保持前缀缓存。提示词要求助手在针对过去的偏好或事实回答“不知道”之前先调用 `recall`。新会话会看到最新记忆，`recall` 始终读取最新内容。

数据位于 `<home>/memory/`：`MEMORY.md` 保存简短事实，`## Index` 用 `[[主题]]` 链接详情；`topics/<主题>.md` 保存主题；`snapshots/<sessionId>.md` 保存冻结块。每条事实占一个列表行，行尾有 `[source: …; added: …; id: …]` 元数据。App 主题编辑器支持每行一条事实，也可带 Markdown 列表符和标题，保存时会补齐元数据。

按 Unicode 字符计数：单条最多 300 字，`MEMORY.md` 最多 4,000 字，每个主题最多 16,000 字，最多 40 个主题。疑似 API 密钥、令牌、私钥、密码的内容会被拒绝，请将凭据存放在对应的秘密存储中。

每次改动先写 `pending.json`，再替换相关文件，最后向 `journal.jsonl` 追加一次事务，记录改动前后的行。启动时以及下次读写前会补完中断的事务，不会重复应用已提交的事务。日志末尾的半行会移入 `journal.torn`。请在服务器停止后备份整个记忆目录，不要在服务器运行时并行手改文件。

记忆是内置功能，默认启用，无需安装或配置。它的开关独立于第三方 `plugins` 配置。要关闭工具和提示词记忆块（记忆页面会显示已禁用），设置：

```yaml
memory:
  enabled: false
```

或使用 `SWIFTNEST_MEMORY=false`，已有记忆仍保留在服务器。仅所有者可访问 HTTP API，使用与其他 App API 相同的签名会话和 Host/Origin 检查：`GET /swiftnest/api/memory`，该前缀下的 `POST /add`、`/edit`、`/delete`，以及 `GET`/`POST /topic`。`packages/api` 提供对应的类型化方法。
