# 核心概念

## 服务器、设备、插件

- **服务器（巢 / Nest）**：一台常开的机器。它登记设备、做权限判断、处理审批、写审计日志，并把所有设备的能力汇总成一个 MCP 端点交给智能体。
- **设备（栖点 / Perch）**：每台被控设备上跑的程序。它托管本机的能力，在本机执行调用，并在本机强制超时和取消。
- **插件**：一切功能的载体。能力、连接方式、交互入口、权限策略、存储……都是插件，官方插件和社区插件地位相同。

一台机器可以同时是服务器和设备。只有一台机器时也能直接试用（练习场就是这样）。

## 工具名

智能体看到的工具名是 `<设备>__<能力>__<工具>`，例如 `laptop__shell__run`。用双下划线而不是点号，是因为 OpenAI、Anthropic 等模型接口的函数名不允许点号。

另外还有几个任务工具：

| 工具 | 作用 |
|---|---|
| `swiftnest__devices` | 列出在线设备和它们的能力 |
| `swiftnest__task_status` | 查看任务状态和结果 |
| `swiftnest__task_wait` | 等任务结束（例如等主人批准） |
| `swiftnest__task_cancel` | 取消等待中或运行中的任务 |

**没有"批准"工具**：智能体永远不能批准自己的请求，批准只能由人在终端或面板里做。

## 风险等级

每个工具声明一个默认风险，能力还可以按具体参数重新判断（例如命令行能力把 `ls` 判为"读"，把 `rm` 判为"敏感"）。

| 风险 | 含义 | 默认 |
|---|---|---|
| `read` 读 | 只观察，不改变任何东西 | 允许 |
| `write` 写 | 改变本机状态 | 询问 |
| `exec` 执行 | 运行代码 | 询问 |
| `sensitive` 敏感 | 删除、改系统、花钱、对外发消息 | 询问（规则也不能把它改成自动允许） |

规则可以按客户端、设备、能力、工具、风险收紧或放宽（敏感操作除外）。

## 任务状态

```
queued（排队） → pending_approval（等批准） → running（运行中） → succeeded（成功）
                                                         ↘ failed / denied / timed_out / cancelled
```

- 需要批准的调用会**立刻**返回"等待批准 + 任务号"，智能体可以先做别的事；
- 每台设备同时运行的调用有上限（默认 4），多出来的排队；
- 无人处理的审批 10 分钟后过期（拒绝）；
- 超时和取消会传到设备上，真正终止对应的进程。

## 审计

每个任务的每次状态变化都写入只追加的审计日志：时间、客户端、设备、能力、工具、**原始参数**、状态、原因、错误。插件没有改写审计日志的途径。

## 错误

所有错误都是统一格式：`code`（错误码）、`message`（哪里错了）、`suggestion`（怎么修）、`retryable`（重试有没有用）。
