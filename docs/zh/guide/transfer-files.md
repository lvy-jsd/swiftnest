# 传输文件

打开 **设备 → 发送文件到…** 或 **传输 → 发送文件到…**，选择来源设备、源文件、目标设备和
目标文件的完整路径。桌面 App 还可以**选择这台电脑上的文件**。文件选择器不会自动共享文件夹：
请先在“这台设备”中添加共享目录。两端都须保持运行；启用后台运行后可以关闭桌面窗口。

也可以对 Ivy 说：“把电脑上的 `/Shared/video.mp4` 发到手机的 `/Shared/video.mp4`。”
Ivy 使用 `transfer_file`，设备名填已配对的 slug；`server` 表示服务器自己的文件区：

```json
{
  "source": { "device": "computer", "path": "/Shared/video.mp4" },
  "destination": { "device": "phone", "path": "/Shared/video.mp4" }
}
```

`transfer_file` 做一次有界的元数据读取后返回传输 ID，不等待整个文件传完。
`transfer_status` 查询进度，`transfer_cancel` 取消传输。App 收到 `transfers-changed` 事件后，
在聊天卡片和传输页显示进度、速度、预计剩余时间，以及暂停、继续、取消和重试操作。
速度按已落盘并确认的字节采样计算，重新校验或等待连接时可能显示零。

## 审批与完整性

源文件须是共享目录内的普通文件；密钥、凭据、浏览器配置和 Swiftnest 私有数据始终受保护，
符号链接也不能绕过限制。目标文件夹须已存在并已共享。已有目标文件会被拒绝，请换一个名称。
主人审核一次**写入**请求，可看到两端身份、路径、文件大小、修改时间和内容前缀哈希。
目标端保存批准记录，同一笔传输恢复时无需再次批准。来源、目标或配对身份发生变化会产生新的 ID，
需要重新批准。移除共享目录后，旧审批也不能绕过重新连接时的路径检查。

文件按 4 MiB 分块，使用 SHA-256 校验每块、前 1 MiB 身份前缀及整个文件，同时只发送一块。
每次确认前先同步磁盘数据和断点日志。损坏块会重传，每次连接尝试最多发送三次。
目标目录内的 `.swiftnest-<传输ID>.part` 暂存文件在整文件哈希正确后才会原子重命名。
续传会比较已确认部分的哈希，损坏的暂存文件从零重传；最终文件名下不会出现半成品。

网络变化后自动重新连接。App 重启后恢复同一配对设备，服务器会按目标端的持久化偏移继续。
暂停状态在服务器重启后仍保留。取消会停止调度并关闭加密流，保留暂存文件及其配额预留；
不再需要时，应在没有传输运行时由主人清理 `.part` 文件和对应收据。
已取消的 ID 无法在 App 中继续；选择新的目标文件名可重新发起。

## 直连、中继与服务器存储

Nest 交换发送端认证连接所用网卡的 IPv4 候选地址。接收端使用新的随机凭证尝试直连，数据仍使用
stream-v1 认证加密；无法到达时两端改走 Nest 中继。不会修改防火墙或路由器。
调试时可以传 `"routing": "relay"` 强制中继。尚未实现 IPv6 候选发现、多网卡选择和 NAT 穿透。
即使数据直连，两端到 Nest 的控制连接也须保持在线。

设备之间传输时，中继仅转发密文。受信任的 Nest 通过已配对的加密控制通道分发每次尝试的密钥，
因此 Nest 本身仍能够推导明文，并不提供对 Nest 的保密性。
设备与服务器传输时，服务器就是明文收发端，文件放在 `config.home/files`；相对路径从这里开始，
区外路径和受保护路径被拒绝，上传同样需要写入审批。

在 YAML 中配置配额：

```yaml
files:
  quotaBytes: 107374182400 # 100 GiB，也是默认值
```

也可设置 `SWIFTNEST_FILES_QUOTA_BYTES`。零配额拒绝非空上传。
已有文件、暂存文件以及已批准上传的剩余大小都计入配额，并发批准按顺序预留容量。
磁盘实际可用空间仍可能小于配额。
服务器私有传输索引为 `config.home/devices/transfers.json`，收据放在
`config.home/devices/file-receipts`；原生目标端使用其私有数据目录下的 `transfers`。
传输运行时请勿编辑收据。

自动验收使用本机回环网络上的两个真实 Linux Rust Perch 和服务器，以 200 MiB 文件验证直连、
中继、进程重启和最终哈希。真实手机性能与原生文件选择器仍需设备验收；中英文界面已用 Chromium
验证 390 像素宽度。
