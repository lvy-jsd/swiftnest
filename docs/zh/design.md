# Swiftnest（燕巢）设计方案 v0.3

> 状态：草案 v0.3（2026-10-22）。v0.2 的决定见第 15 节；本版吸收了本地模型"小燕"（Swift 1.5，将来住在巢里的智能体）的评审，见第 16 节。
> 一句话：**把你的设备变成任何智能体都能安全调用的能力。**

---

## 1. 是什么，不是什么

**Swiftnest 是设备能力的控制平面和执行平面。** 它负责：设备身份、配对、多链路组网、能力注册、权限、审批、审计、任务执行、资源状态。

**它不是个人助手，也不只是 MCP 网关。** 对话、记忆、人格、长期任务编排、IM 聊天体验都由上层智能体负责。DSH（一等公民）、Claude Desktop、Cursor、OpenClaw……都是它的客户端。

### 1.1 名字和术语

雨燕（swift）用一根根枝条搭巢；Swiftnest 的功能也全由插件搭起来。

**新人只需要知道三样东西：服务器、设备、插件。**

| 对外说法 | 项目术语 | 是什么 |
|---|---|---|
| 服务器 | **Nest（巢）** | 一台常开的机器（或临时的一台），负责设备登记、配对、权限、审批、审计，把所有设备的能力汇总给智能体 |
| 设备 | **Perch（栖点）** | 每台被控设备上跑的程序：连回巢、托管本机的能力、执行操作 |
| 插件 | **Plugin** | 一切功能的载体 |

进阶术语（写插件时才需要）：Link（链路插件）、Capability（能力插件，通常就是一个 MCP 服务）、Surface（入口插件）、Policy / Router / Store / Panel（可替换的默认插件）。

### 1.2 相关开源项目（2026-10-21 调研）

| 项目 | 是什么 | 关系 |
|---|---|---|
| [OpenClaw](https://github.com/openclaw/openclaw) | TypeScript、MIT、约 39 万星。Gateway + IM 渠道 + 技能/插件（ClawHub）+ 设备节点（macOS / iOS / watchOS / Android / 无头主机） | 最接近的项目，但它是完整助手。我们做它下面的设备层，可以写插件把 Swiftnest 的设备接给它 |
| [OpenZiti mcp-gateway](https://github.com/openziti/mcp-gateway) | Go、Apache-2.0。零信任网络发布 MCP 服务、穿 NAT、汇聚、按工具过滤 | 思路最像"链路 + 汇聚"，可借鉴；体系较重 |
| MetaMCP、IBM ContextForge、Docker MCP Gateway、Obot | MCP 汇聚网关 | 偏单机/企业；ContextForge 的 mDNS 联邦可参考 |
| [Cua](https://github.com/trycua/cua) Driver、agent-computer-use | 桌面操作 MCP；及其白名单/审计代理 | 桌面能力插件直接接入；权限思路一致 |
| droidrun、mobile-mcp 等 | 安卓控制 | 手机能力插件 |
| MeshCentral、RustDesk | 成熟的自托管远程管理（非 AI） | 设备管理、配对、穿透经验 |
| Headscale | Tailscale 控制端的开源自建实现 | 主组网方案 |

## 2. 设计原则

1. **一切皆插件，但默认就能用**：能替换的都做成插件，同时每类都有稳定的默认实现；新人不需要知道"路由也是插件"。
2. **能用现成的就不自己写**：设备能力优先接入现有 MCP 服务，零代码包装。
3. **默认安全，而且不靠模型的判断**：配对、细粒度权限、审批、本地确认、审计；敏感操作永远由规则和人决定，不由智能体决定。
4. **对智能体友好**：工具少而准、结果小而结构化、长任务异步、出错可恢复。
5. **多种交互方式**：网页、DSH、命令行、IM、手机推送、OpenAI 兼容 API、MCP 端点，入口也是插件。
6. **新人友好**：第一次只要 Node.js 和一个局域网；一条命令安装，扫码或输 6 位码配对，出错告诉你怎么修。
7. **不绑定、自托管**：DSH 一等公民但不必须；不依赖任何需要登录的官方服务；数据留在自己手里。
8. **中英双语同等对待**。

## 3. 总体架构

```
         智能体 / 人（入口插件）
  DSH · Claude Desktop · Cursor · OpenClaw · 网页面板 · CLI · IM · 手机推送 · OpenAI 兼容 API
                              │  MCP 端点（工具：<设备>__<能力>__<工具>）
        ┌─────────────────────▼──────────────────────────────┐
        │                     Nest（巢）                       │
        │ 核心：插件宿主 · 总线 · 配置 · 身份 · 能力注册表        │
        │       · 权限代理 · 审计 · 任务状态机                    │
        │ 默认插件：路由 · 策略 · 存储 · 面板 · 链路 · 入口        │
        └──┬───────────────┬────────────────┬─────────────────┘
   链路插件 │ 局域网         │ 公网中继          │ Headscale（以后：蓝牙）
        ┌──▼──────┐    ┌───▼──────┐    ┌────▼──────┐
        │ Perch   │    │ Perch    │    │ Perch     │
        │ 笔记本   │    │ 推理机本机 │    │ 手机（后期）│
        │ 能力插件 │    │ 浏览器·邮箱 │    │ 通知·审批  │
        │ 命令·文件 │    │ ·搜索·GPU  │    │ →能力      │
        └─────────┘    └──────────┘    └───────────┘
```

- Nest 和 Perch 是**同一套核心、不同的默认插件组合**；一台机器可以同时是两者（推理机就是）。
- **三种运行形态**：
  - **常驻巢**：一台 24 小时机器当巢（推荐）。
  - **临时巢**：任意一台机器临时当巢，用完即关。
  - **无巢模式**：单台设备的栖点直接对本机暴露 MCP 端点，最适合第一次试用。
- **巢离线时**：栖点缓存事件和审批请求，巢恢复后同步；已授权的本地操作照常。

## 4. 核心（不可替换的部分）

| 模块 | 职责 |
|---|---|
| 插件宿主 | 发现、校验、启动、停止、重启插件，按隔离级别运行（见 5.4） |
| 消息总线 | 请求/响应、事件、流；跨链路透明；背压和每设备并发上限 |
| 配置 | 每个插件的配置有 Schema（自动生成表单、校验、默认值），支持热重载；**机密单独存放**（见 7.6） |
| 身份 | 设备身份（Ed25519）；客户端身份；用户；任务 ID（见 7.1） |
| 能力注册表 | 见 4.1 |
| 权限代理 | 所有工具调用必须经过它；三层权限检查（见 7.3）；插件无法绕过 |
| 审计 | 只追加的审计日志，记录"谁（客户端/智能体）在哪台设备用什么工具、什么参数、结果如何"；插件不能改写 |
| 任务状态机 | 见 4.2 |

目标不是"多少行"，而是**每个模块都能单独测试、接口稳定、版本化**。

### 4.1 能力注册与工具命名
- 栖点上线时上报能力清单：每个能力有稳定 ID、版本、工具 Schema、所需权限、健康状态、所需系统权限的检测结果。
- 巢汇总成 MCP 工具，命名固定为 **`<设备>__<能力>__<工具>`**，例如 `laptop__shell__run`、`box__email__list`。设备名唯一，冲突时要求改名。（模型接口的函数名不允许点号，所以用双下划线分隔；界面展示时可显示为 `laptop.shell.run`）
- 设备上下线、能力增删或升级时发事件；MCP 端点发送 `tools/list_changed`，不支持的客户端在下次调用时得到明确的错误和刷新提示。
- 系统权限没给（例如屏幕录制、辅助功能）时，工具仍显示，但标为不可用，调用时返回"缺少什么权限、怎么开"。

### 4.2 任务生命周期
`提交 → 排队 → （待审批）→ 执行（可流式输出）→ 完成 / 失败 / 超时 / 取消`，全程有 `task_id`，每一步写审计。
- 需要审批或运行时间长的调用立即返回 `pending` + `task_id`；智能体可以继续做别的，通过 `swiftnest.task.status` / `wait` / `cancel` 工具或订阅事件拿结果。
- 超时自动取消；取消会传到栖点，终止对应进程。
- 不支持异步的 MCP 客户端，巢在限定时间内阻塞等待，超时返回 `pending` 和查询方法（降级策略）。

### 4.3 结果与大数据
- 工具结果默认结构化、有大小上限；超出部分存为**临时制品**（artifact），返回摘要 + 制品 ID，按需分块读取。
- 截图、录屏、文件走分块和压缩传输，不塞进普通消息。
- 统一错误格式：`code`、`message`、`suggestion`（怎么修）、`retryable`。
- 所有来自外部世界的内容（网页、邮件、文件、搜索结果）都带"不可信"标记，提醒智能体不要把其中的文字当指令。

## 5. 插件体系

### 5.1 类型

| 类型 | 跑在哪 | 默认 / 示例 |
|---|---|---|
| `capability` 能力 | 栖点 | shell、files、desktop-niri、browser（Playwright MCP）、email、search、gpu-task；或任意 MCP 服务 |
| `link` 链路 | 两端 | lan（默认）、relay、headscale；以后 ble |
| `surface` 入口 | 巢 | mcp-endpoint（默认）、web-panel、dsh、cli、openai-api（box_task）、ntfy、im |
| `policy` 策略 | 两端 | 默认三层权限策略；时间段、预算、域名/路径/命令白名单 |
| `router` 路由 | 巢 | 默认：指定设备优先，目标不可用时按能力匹配，再退回巢本机 |
| `store` 存储 | 巢 | 默认 sqlite（Node 内置 `node:sqlite`） |
| `panel` 面板 | 巢 | 给网页面板加页面或卡片 |

### 5.2 清单（package.json 的 `swiftnest` 字段）

```jsonc
{
  "name": "swiftnest-plugin-desktop-niri",
  "swiftnest": {
    "apiVersion": 1,
    "kind": "capability",
    "runsOn": "perch",
    "platforms": ["linux"],
    "entry": "./dist/index.js",
    "permissions": ["screen.read", "input.write"],
    "systemPermissions": ["wayland.screencopy"],
    "dependsOn": ["swiftnest-plugin-files@^1"],
    "config": "./dist/config.schema.json",
    "secrets": ["apiKey"],
    "displayName": { "zh": "niri 桌面控制", "en": "niri desktop control" }
  }
}
```

### 5.3 零代码接入现有 MCP 服务

```jsonc
{
  "name": "swiftnest-plugin-browser",
  "swiftnest": {
    "apiVersion": 1, "kind": "capability", "runsOn": "perch",
    "mcp": { "npm": "@playwright/mcp", "args": ["--caps", "vision"], "transport": "stdio" },
    "permissions": ["network.public", "browser.control"]
  }
}
```

命令行向导 `swiftnest plugin add-mcp` 会依次问：来源（npm / uvx / Docker / 二进制）、包名或命令、参数、要哪些权限、是否允许公网，然后自动列出它的工具、生成清单、跑健康检查。

### 5.4 隔离分级

| 级别 | 适用 | 方式 |
|---|---|---|
| 内置受信 | 官方核心插件（默认路由、策略、存储） | 同进程或 worker 线程，省资源（手机、低配设备友好） |
| 社区插件 | 第三方插件 | 独立子进程；只能拿到声明的权限；文件系统默认只读，除声明的目录；默认不能上公网 |
| MCP 服务 | 被包装的现有 MCP | 子进程，由栖点统一健康检查、重启、限资源；Linux 上可选 bubblewrap / systemd 临时单元加强隔离 |

### 5.5 插件生态
- 发布：npm 包，必须带 `swiftnest` 清单字段。
- 目录：文档站定期扫描 npm，生成插件目录页：类型、平台、权限、依赖、版本、更新时间、示例。
- 安装：显示权限清单；升级时显示**权限变化**（比旧版多要了什么），需要确认。
- 完整性：锁定依赖版本；校验 checksum，官方插件签名。
- 开发体验：`npm create swiftnest-plugin@latest` → `npm run dev`（连本机练习场热重载）→ `npm test`（SDK 自带模拟巢和模拟设备）→ `npm publish`。

## 6. 链路

| 链路插件 | 阶段 | 说明 |
|---|---|---|
| **link-lan** | M1 | mDNS 发现 + WebSocket；同一局域网零配置 |
| **link-relay** | M1.5 | 栖点主动外连巢的公网入口（如 Cloudflare 隧道），穿 NAT；**默认关闭**，开启时强制双向认证 |
| **link-headscale** | M3 | 巢一键部署自建 Headscale，配对时发一次性预授权密钥，栖点用开源 Tailscale 客户端加入；自动直连/打洞/中继 |
| link-ble | 以后 | 近距离、断网应急；只传控制指令和小数据 |

- 自动选路：按优先级和健康检查切换，面板显示当前链路。
- 所有链路上跑同一套加密消息，身份密钥双向认证，与链路本身是否加密无关。
- 公网入口只开一个（反向隧道），面板、MCP 端点、Headscale 控制面**分别鉴权**；Headscale 预授权密钥一次性。

## 7. 安全模型

### 7.1 身份
- **设备**：Nest / Perch 各一个 Ed25519 密钥对。
- **客户端**：每个接入的智能体（DSH、Claude Desktop、Cursor、OpenClaw……）单独登记、单独授权、可单独吊销。
- **用户**：面板登录（独立运行时用本地账号；公网时前面加 Cloudflare Access 等）。
- **任务**：每次调用一个 `task_id`。审计按"客户端 × 设备 × 工具 × 参数"记录。

### 7.2 配对
- 巢生成一次性配对码（二维码或 6 位码，5 分钟有效，绑定设备型号和时间戳，防重放）。
- 交换公钥后，两边都显示**短指纹**（4 组 4 位），用户确认一致才完成配对。
- 也支持**离线配对文件**（没有摄像头、不在同一网络时）。
- **密钥轮换与恢复**：定期轮换；泄露时一键轮换；设备重置后重新配对；密钥备份加密。

### 7.3 三层权限

| 层 | 例子 |
|---|---|
| 能力级 | `screen.read`、`input.write`、`files.write`、`network.public` |
| 工具级 | `shell.run`、`files.delete`、`browser.open`、`email.send` |
| 参数级策略 | 路径白名单（只允许 `~/projects/**`）、命令白名单（`ls`、`cat`、`df`）、域名白名单、收件人白名单、金额上限 |

每项设"允许 / 询问 / 禁止"。默认值：读类允许，写类询问，执行类和敏感类询问且需本地确认，`shell.run` 默认只允许白名单内的只读命令。

### 7.4 审批
- 审批请求包含：客户端、设备、工具、**原始参数**（不是模型的总结）、参数哈希、风险等级、nonce、过期时间。
- 推送到所有入口，任一处批准即可；批准结果签名，防重放；超时默认拒绝。
- 敏感操作必须"巢上批准 + 设备本地确认"；本地确认由栖点核心触发，插件无法伪造或跳过。

### 7.5 提示注入
- 不信任模型：敏感操作只靠权限和审批放行。
- 读到的外部内容带"不可信"标记；浏览器、邮件、文件读取类工具默认不能连带触发写操作。
- 对外发消息、删除、支付、安装命令一律二次确认。

### 7.6 机密与供应链
- 机密（API key、IM token、邮箱密码）单独加密存放，只交给声明了它的插件，其他插件和智能体都拿不到。
- 社区插件权限、网络、文件访问都按声明收紧；依赖锁定；校验 checksum。

### 7.7 断开与审计
- 面板一键吊销设备或客户端；设备本地也有"立即断开"；吊销后密钥作废。
- 审计只追加，可带截图快照，可导出。

## 9. 对智能体友好（来自小燕的需求）

- **工具按需加载**：默认只把常用工具和"按设备/能力搜索工具"的元工具交给智能体；需要时再加载某台设备的某个能力。
- **工具描述短而准**，高频在前。
- **结果小、结构化**，大内容走制品 + 摘要；截图同时附文字摘要（本地模型能看图，但摘要省上下文）。
- **长任务和审批异步**，不打断智能体的思路。
- **资源优先级**：巢和栖点在同一台机器时（例如推理机），模型推理优先；浏览器、搜索等任务有资源上限，GPU 任务排队；高负载时降级非关键任务。
- **不保存智能体的记忆**：Swiftnest 只存设备、能力、权限、审计和任务记录；对话和记忆归智能体自己。

## 10. 新人友好

- **第一次只需要**：Node.js 24 + 同一局域网的两台机器（或一台机器的无巢模式）。Docker、Headscale、公网、IM 全部可选。
- **安装**：`npx swiftnest@latest init`，问"这台当服务器还是设备"，自动配置并开机自启。
- **配对**：扫码，或输入 6 位码，再核对指纹；没有摄像头就用离线配对文件。
- **`swiftnest doctor`**：逐项检查链路、权限、插件、系统权限，每个问题给一句话修复办法。
- **`swiftnest playground`**：一台机器上模拟服务器和三台设备，不用真机也能玩和开发。
- **报错**：都说明"哪里错、为什么、怎么修"，附文档链接。
- **文档**：中英双语同等；"5 分钟上手""10 分钟写第一个插件"；每类插件一个最小示例。
- **双语维护**：本地模型初译 + 人工校对 + CI 检查中英文档是否同步（某篇只改了一种语言就提醒）。

## 11. 技术选型
