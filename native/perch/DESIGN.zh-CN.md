# 原生设备端设计

[English](DESIGN.md)

本模块将设备端能力放入 Rust 核心，供桌面和 Android 宿主调用。Nest、权限审批和审计仍由服务器负责。
App 不启动 Node，也不持有 Nest 管理密钥。桌面宿主通过 Tauri 命令调用 Controller，Web 与移动界面
根据支持情况隐藏桌面控制选项。

## 身份与连接

设备身份密钥和配对信息保存在应用数据目录，使用受限权限；Windows 使用 ACL。
设置包括显示名称、稳定 slug、共享目录、服务器 URL、是否启用控制、后台运行和实时画面授权。
显示名称可修改，slug 保持稳定。断开不会自动删除配对；unpair 停止控制并清除服务器身份。

加密连接兼容 TS channel v1，使用 Ed25519 身份、X25519 临时交换、HKDF 派生和 AES-GCM 数据帧。
双向计数器拒绝重放和乱序；握手和身份确认有超时、大小限制，协议版本不兼容时终止。
TLS 使用 rustls ring provider，设备端可独立运行，不依赖宿主恰好选择了 provider。

首次配对需要六位码和双端指纹确认。没有交互确认时不能静默接受新服务器。
服务器地址与已保存身份绑定，更改地址需要重新配对。终止错误（撤销、身份变化等）不无限重试；
临时断连进入离线重连。关闭、休眠和紧急停止都会取消进行中的操作。

## 能力与权限

files、shell、screen、input、transfer 通过稳定 manifest 暴露工具。分类结果包含风险和人可读理由；
只读操作可按策略直接通过，写入、命令执行、敏感操作需要服务器所有者审批。

PathGuard 解析真实路径和符号链接，限制在共享目录内。密钥、凭据、浏览器和 Swiftnest 自身数据
始终受保护；不能通过 symlink、相对路径或删除共享根目录绕过边界。
文件读取和列表有大小限制，文件内容标记为外部未信任数据。写入拒绝覆盖冲突目标。

shell 识别只读列表、破坏性命令、shell 操作符和越界路径。Linux 通过 bubblewrap 实施文件系统限制，
macOS 使用 sandbox 配置；没有合适沙箱的平台拒绝执行。输出、并发和执行时间均有限制。
取消会终止对应进程组，不应留下后台子进程。

## 截图、输入和实时画面

Linux 支持 X11、wlroots 和 ScreenCast/RemoteDesktop portal 路径，Windows 使用原生桌面 API。
后端缺失或未授权时明确失败。坐标绑定 displayId、captureId、缩放和截图几何信息；
显示器变化或截图过期后需要重新截图。屏幕内容始终视为未信任数据。

实时画面默认关闭，需要可见托盘指示。只允许一个查看端，连接有租约、确认、频率和队列限制。
所有者接管时先发布暂停，再排空在途智能体输入；交还后智能体才能继续输入。
托盘菜单和通知提示桌面正在共享，可立即停止。退出、禁用、撤销和租约到期释放全部流。

## 文件传输

文件流与屏幕流分离，使用绑定来源、目标、路径和身份的独立凭证与密钥。
目标写入需要一次审批；大文件分块加密，支持确认、断点续传、逐块和整文件哈希。
续传信息不能跨不同配对身份或不同来源文件复用。临时文件不得为符号链接，
目标存在时拒绝覆盖；取消、断连、错误和关闭均释放资源。

## 宿主和语言

宿主负责选择文件夹、文件选择窗口、托盘、通知以及用户确认。后台和实时画面要求托盘可用。
Android 不提供桌面文件选择和桌面控制，相关错误使用中文默认、可选英文的共享 native/locale 目录。
错误保留 code，提供本地化 message 与 hint，底层诊断保留在内部 diagnostic 中。
App 语言选择通过 set_language 更新并原子保存，下次启动恢复。
